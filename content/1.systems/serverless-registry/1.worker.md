The Worker is the registry itself. It serves the native read protocols of the package managers, the
publishing and administration API (`/api/v1`) and a landing page with an admin panel. Files are kept in
[CloudFlare R2](https://developers.cloudflare.com/r2/){:target="_blank"}, credentials in
[CloudFlare KV](https://developers.cloudflare.com/kv/){:target="_blank"}.

## Deployment

Pick one of three ways, all using the same repository:

| Path | For whom | Deploys on |
| --- | --- | --- |
| *Deploy to CloudFlare* button | most installations | every push to your `main` |
| Fork + GitHub Actions | those who prefer GitHub Actions | every push to your fork's `main` |
| Local `npm run deploy` | developers and one-off installs | every time you run it |

Everything is provisioned from `wrangler.jsonc` on the first deploy: the Worker `serverless-registry`,
a KV namespace (`AUTH`), an R2 bucket (`R2_BUCKET`), static assets and an hourly cron cleanup.
Nothing installation-specific is committed - settings live in the CloudFlare dashboard, so updates are conflict-free.

## Configuration

Set in the Worker's *Settings* → *Variables and Secrets*:

| Variable | Type | Description |
| --- | --- | --- |
| `PUBLIC_URL` | variable | Public address of the registry (also the audience of OIDC tokens). |
| `S3_ENDPOINT` | variable | R2 S3 endpoint used for presigned URLs. |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | secrets | R2 API token scoped to the bucket. |
| `SESSION_SECRET` | secret | Signs panel sessions (`openssl rand -base64 48`). |

Optional variables (defaults apply while unset):

| Variable | Default | Effect |
| --- | --- | --- |
| `ECOSYSTEMS` | `composer,npm,cargo,generic,nuget,swift,maven` | Enabled ecosystems; a disabled one answers `404`. |
| `MAX_UPLOAD_BYTES` | `536870912` (512 MiB) | Largest accepted file of a version. |
| `APPEND_WINDOW_HOURS` | `24` | How long files may be appended to a generic version. |
| `TOKEN_PREFIX` | empty | Fixed prefix (e.g. `srg_`) for issued tokens, so leaked ones can be found with grep. |
| `CHECK_UPDATES` | `true` | Settings page checks GitHub for a newer release once a day. |
| `R2_BUCKET_NAME` | `serverless-registry` | Bucket name in presigned URLs. |

## Authentication

Every credential is a project name with exactly one kind, a list of grants and one or more secrets:

- `read` - installs packages; its key token is safe to commit into the consumer's repository (`auth.json`, `.npmrc`, ...),
- `publish` - publishes versions with `sreg`, usually from GitHub Actions; never reads,
- `admin` - the panel and the administrative API.

A grant is an ecosystem, a package name or `vendor/*` pattern and a version constraint in that ecosystem's syntax.
`read` grants are transitive by default. A token has the form `<project>:<secret>`.

A `publish` credential can also carry a `gh` secret, which trusts a GitHub repository (optionally restricted to
a ref, workflow or environment) so pipelines authenticate with OIDC, without any stored secret. See the
[deployment guide](https://github.com/kduma-OSS/serverless-registry-worker/blob/main/docs/deployment.md#a-publish-credential-for-github-actions-oidc-no-secret){:target="_blank"}.

## Admin panel

Opening the registry in a browser shows a small panel, rendered by the Worker without any framework or external resources.

### First run

While the registry has no credential at all, the page offers to create the first admin. Enter a project name and either
leave the password empty (the Worker generates a token) or choose a password of at least 12 characters.

![First run](/systems/serverless-registry/panel-first-run.png)

The token is shown **only once** - store it in a password manager or a CI secret. The form never appears again.

![Admin created](/systems/serverless-registry/panel-admin-created.png)

### Login

Paste a token, or switch to *login and password* and enter the two sides of the token's colon.
A signed session cookie keeps you signed in for 12 hours.

![Login](/systems/serverless-registry/panel-login.png)

### Browsing packages (`read` credentials)

A `read` credential sees every package its grants cover, with an ecosystem badge, the number of versions and the latest version.
A filter bar narrows the list by name and ecosystem.

![Packages visible to a read credential](/systems/serverless-registry/panel-packages-read.png)

A package page lists its versions and has ready-to-paste client configuration with copy buttons
(a command, files or environment variables - pick one with the chooser). Replace `<token>` with your token.

![Package page with client configuration](/systems/serverless-registry/panel-package.png)

A version page lists its files with sizes and checksums, downloads them through a short-lived presigned link
and shows how to install exactly that version.

![Version page](/systems/serverless-registry/panel-version.png)

### Administration (`admin` credentials)

An admin gets three pages in the header.

**Packages** - the same list with *Reindex* and *Delete* on each row; a package's page also lets you yank or delete its versions.

![Packages (admin)](/systems/serverless-registry/panel-admin-packages.png)

**Credentials** - every project in a table, plus a *New credential* form that shows the new token once.

![Credentials](/systems/serverless-registry/panel-admin-credentials.png)

A credential has the tabs *Overview*, *Grants*, *Secrets* and *Danger zone*. Grants are an ecosystem, a package name or
`vendor/*` pattern and a version constraint in that ecosystem's syntax:

![Credential grants](/systems/serverless-registry/panel-credential-grants.png)

Secrets are `key` tokens or GitHub Actions `gh` entries (OIDC) that trust a repository, optionally restricted to a ref, workflow or environment. They can be expired individually:

![Credential secrets](/systems/serverless-registry/panel-credential-secrets.png)

**Settings** - the running version, the variables (set in the dashboard or defaults) and, unless `CHECK_UPDATES` is `false`, whether a newer release exists.
Secret values are never shown.

![Settings](/systems/serverless-registry/panel-settings.png)

## Compatibility

The Worker and `sreg` are released independently. The Worker answers with the oldest accepted client in
`X-Min-Client-Version` and rejects older ones with `426` (`sreg` exit code `3`). The previous API version is kept
for at least one minor release after an incompatible change.
